# 自動更新の調査（未実装）

**現時点で hanamask に自動更新の仕組みは無い。**修正を配ってもインストーラーを再度落として実行してもらうしかなく、**利用者が古いまま気付かない。**実際 0.2.0 には「エージェントがノート本文を書き換えられない」不具合が入っており、0.2.1 で直したが、届ける手段が無い。

対象読者は管理者。実装の可否を判断するための材料をまとめる。

## 1. 使う道具

`electron-updater`（2026-08-10 時点で 6.8.9、MIT）。直接依存は8件（`semver` / `js-yaml` / `fs-extra` / `lazy-val` / `lodash.isequal` / `tiny-typed-emitter` / `lodash.escaperegexp` / `builder-util-runtime`）。**依存の追加は `docs/GOVERNANCE.md` §6 により管理者の承認が要る。**

配布側の準備は既にできている。`electron-builder.yml` に `publish` を宣言済みで、リリースのたびに `latest.yml`（更新の目印）が作られ GitHub Releases に添付されている。**アプリ側が読みに行っていないだけ。**

## 2. 前提: リポジトリの公開が要る

更新の目印は `https://github.com/<owner>/<repo>/releases/download/...` から取りに行く。**非公開リポジトリだと、アプリの中にアクセストークンを埋め込むことになる。**配布物に埋めたトークンは秘密ではないので、この形は取らない。

**つまり自動更新は、リポジトリ（少なくともリリース）を公開する判断とセットになる。**

## 3. 未署名との組み合わせ（最重要）

インストーラーには署名を付けない判断をしている（[SIGNING.md](SIGNING.md)）。この状態で自動更新を入れるとどうなるかを、`electron-updater` の実装を読んで確かめた。

**署名の検証は、丸ごとスキップされる。**

```js
// NsisUpdater.js
async verifySignature(tempUpdateFile) {
  publisherName = (await this.configOnDisk.value).publisherName;
  if (publisherName == null) {
    return null;   // ← 検証せず「問題なし」として先へ進む
  }
  ...
}
```

`publisherName` は署名証明書から作られる値で、**未署名のビルドでは存在しない。**つまり「検証に失敗する」のではなく「検証されない」。

### では何が守られているのか

| 守り | 未署名でも効くか |
|---|---|
| 配信経路の暗号化（HTTPS） | **効く** |
| `latest.yml` に書かれた **sha512 との照合** | **効く**（`DownloadedUpdateHelper` が突き合わせる） |
| 配布元が本人であることの証明（署名） | **効かない** |

**`latest.yml` 自体も同じHTTPS経路で取ってくるので、その経路とGitHubを信頼することが前提になる。**

### 判断材料

**この信頼の形は、今の手動配布と同じ**である。利用者はいま、同じHTTPS経路で同じ場所から未署名の `.exe` を落として実行している。**自動更新を入れても、信頼の前提は増えない。**

変わるのは頻度と自動性で、**一度信頼した経路が後から侵害された場合の影響が大きくなる**（利用者が気付かないうちに置き換わる）。ここを重く見るなら、自動更新より先に署名を検討することになる。

## 4. 実装するとしたら

1. `electron-updater` を追加する（**承認が要る**）
2. main プロセスで起動時に更新を確認し、**利用者に知らせてから**適用する。黙って再起動しない
3. **`HANAMASK_DB_PATH` 指定時（E2E）は動かさない。**テストのたびに更新を取りに行くのは無駄で、外部への通信も増える
4. 更新の確認に失敗してもアプリは普通に使えること（ネットワークが無い環境で起動できなくなってはいけない）
5. E2Eでは「更新が無いときに何も起きない」ことだけ確かめる。**実際の更新適用は、リリース済みのバージョン同士でしか試せない**

## 5. 現時点の結論

**リポジトリを公開する判断が出るまでは実装できない。**公開する場合も、署名の判断（[SIGNING.md](SIGNING.md)）と合わせて考える必要がある。

それまでの間、修正を届ける手段は「リリースページから落とし直してもらう」しかない。**READMEとリリースノートに、更新の確認方法を書いておくのが現実的な次善策。**
