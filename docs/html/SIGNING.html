インストーラーの署名

hanamask の Windows インストーラー（.exe）にコード署名を施すために必要なものと、選択肢ごとのタスク・効果・費用の調査結果。対象読者は管理者。

現在のインストーラーは未署名である（2026-08-08、PEヘッダの証明書テーブルが空であることを確認）。

1. 署名して何が変わるか（効果）

「SmartScreenの警告が消える」だけではない。署名の有無で変わるものを分けて把握しておく。

変わること未署名の今署名後備考
SmartScreenの青い警告出る。「詳細情報」を押さないと実行できないEVは即座に消える。OVは評価が貯まるまで出続ける最も大きい効果。初見の利用者はここで止まる
UACダイアログの発行元表示「不明な発行元」証明書の名義（組織名・個人名）署名すればOV/EVを問わず即座に変わる
ウイルス対策ソフトの誤検知未署名バイナリを疑わしいものとして扱う製品がある減る（無くなるわけではない）効果は製品によって差がある
winget での配布登録審査を通らない可能性が高い応募できるwinget経由のインストールはSmartScreenの経路を通らない
ブラウザのダウンロード警告出ることがある減るSmartScreenの評価と連動する

OVとEVの差は「警告が消えるまでの時間」に集約される。OVでも署名自体は有効で、発行元表示・誤検知・winget への効果は同じ。OVは配布本数が増えるにつれて Microsoft 側の評価が貯まり、いずれ警告が消える（貯まるまでの本数・期間は公表されていない）。EVはこの待ちを買うもの。

2. 前提となる業界ルール

  • 2023年6月以降、秘密鍵のハードウェア保管が必須（CA/Browser Forum）。PFXファイルを買って終わり、という形はもう取れない。USBトークンかクラウドHSMのいずれかになる
  • 2026年3月1日以降、公的に信頼されるコード署名証明書の最大有効期間は458日に制限されると報告されている（SSL.com）。「3年分をまとめて買う」形の商品でも、実際の証明書は短期で再発行される運用になる
  • タイムスタンプの付与は必須。 付けないと、証明書の有効期限が切れた瞬間に既に配布済みのバイナリまで「無効な署名」として扱われる。有効期間が458日に短縮されるため、この重要度は上がっている

選択肢A: 署名しない（現状維持）

費用0円
タスク配布ページに警告の回避手順（「詳細情報」→「実行」）を書く。1時間程度
効果SmartScreenの警告は残る。発行元は「不明な発行元」のまま
向くケース管理者本人と、事情を説明できる限られた相手だけに配る場合。実害は「毎回警告を押しのける手間」に留まる

選択肢B: Azure Artifact Signing（旧 Trusted Signing）

Microsoftのマネージド署名サービス。証明書の購入・保管をMicrosoft側に寄せられる。

費用月額 $9.99（Basic、月5,000署名まで）。Premiumは $99.99
名義組織のみ。日本は組織なら対象。個人開発者は米国・カナダ在住者に限られ、日本の個人は対象外（Microsoft Learn）
証明書の格OV相当（SmartScreenの警告は評価が貯まるまで残る）
CI自動署名できる（クラウド署名。Japan Eastリージョンあり）
審査期間本人確認に 1〜20営業日（追加書類を求められるとさらに延びる）

この選択肢を採れるかどうかは、hanamask を法人名義で出すか個人名義で出すかで決まる。個人名義なら日本からは選べない。

採用する場合のタスク

  1. Azureサブスクリプションを用意する（請求先アカウントの種別が Individual だと個人検証しか通らないため、組織として登録する）
  2. Microsoft.CodeSigning リソースプロバイダを登録する
  3. Artifact Signing アカウントを作成する（Japan East）
  4. Identity validation（組織）を申請する — 法人名・登記情報・Webサイト・2種類のメールアドレスが要る。ここが1〜20営業日
  5. 証明書プロファイル（Public Trust）を作成する
  6. electron-builder.yml に署名設定を追加し、ローカルで署名済み .exe を1本作って Get-AuthenticodeSignature で検証する
  7. docs/PACKAGING.md に署名手順を追記する

選択肢C: Certum Open Source Code Signing

オープンソース開発者向けの安価なOV証明書。個人名義で取得できる。

費用年 $50〜70程度（Certum Store）
名義個人可
証明書の格OV相当
前提対象プロジェクトがオープンソースであること。hanamask のリポジトリは現在 private のため、このままでは条件を満たさない
CI自動署名クラウド署名オプションを選べば可能。USBトークンを選ぶと不可

採用するにはリポジトリの公開が必要で、これはアーキテクチャではなく事業判断。docs/GOVERNANCE.md §6 の管理者承認事項にあたる。

選択肢D: 商用のOV/EV証明書（GlobalSign・SSL.com・DigiCert等）

費用OV 年3〜7万円 / EV 年6〜12万円
名義個人事業主でも屋号で取得できる事業者がある（実例）
証明書の格EVを選べばSmartScreenの警告が即座に消える。これは他の選択肢では買えない
CI自動署名クラウドHSM（SSL.com eSigner、DigiCert KeyLocker）を選べば可能

4. どう選ぶか

判断の分岐は「誰に配るか」の一点。

  • 限られた相手に配る → 選択肢A。年数万円と審査の手間に見合う効果が無い
  • 不特定多数に配り、初見の利用者に警告を見せたくない → 選択肢D（EV）。警告が即座に消えるのはEVだけ
  • 不特定多数に配るが、警告が消えるまで待てる → 法人名義なら選択肢B（月$9.99が最安）、個人名義でリポジトリを公開できるなら選択肢C

5. 共通の設定作業

どの選択肢でも electron-builder.yml への追記が要る（現在は署名関連の記述が一切ない）。

win:
  signtoolOptions:
    signingHashAlgorithms: ["sha256"]
    rfc3161TimeStampServer: "http://timestamp.digicert.com"

証明書の指定方法は保管形態によって変わる（証明書ストア経由なら certificateSubjectName、クラウド署名なら各サービスのdlkit/署名プラグイン）。

6. 現状の確認方法

# PEヘッダの証明書テーブルを直接見る（外部ツール不要）
python3 -c "
import struct
d = open('release/hanamask Setup 0.1.0.exe','rb').read(4096)
pe = struct.unpack_from('<I', d, 0x3C)[0]
magic = struct.unpack_from('<H', d, pe+24)[0]
base = pe + 24 + (112 if magic == 0x20B else 96)
rva, size = struct.unpack_from('<II', d, base + 32)
print('署名:', 'あり' if size > 0 else 'なし')
"

Windows 側からは Get-AuthenticodeSignature <path> でも確認できる（WSLからは powershell.exe -NoProfile -Command "Get-AuthenticodeSignature '<Windowsパス>'"）。
